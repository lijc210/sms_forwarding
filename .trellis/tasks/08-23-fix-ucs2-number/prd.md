# 修复短信 UCS-2 编码号码解析

## 问题描述
部分调制解调器（如 SIMCom 系列）在 `AT+CMGF=1` 文本模式下，仍会将手机号码字段以 UCS-2 十六进制格式输出（如 `02830203`），而不是 ASCII 文本。当前的正则表达式只匹配带引号的号码（如 `"38885"`），无法匹配未加引号的 UCS-2 编码号码，导致这些短信被完全跳过。

## 根因分析
1. 正则 `r'\+CMGL:\s*(\d+),"(.*?)","(.*?)"'` 中 `"(.*?)"` 要求号码被引号包裹
2. UCS-2 编码的号码不带引号（如 `02830203`），正则无法匹配
3. 即使匹配到，号码字段也未经过 UCS-2 解码

## 修复方案
1. 修改正则表达式，同时匹配带引号和不带引号的号码字段
2. 对匹配到的号码字段进行 UCS-2 解码判断和处理
3. 短信内容的 UCS-2 解码逻辑已正确，无需修改

## 验收标准
- 带引号的 ASCII 号码（如 `38885`）正常显示
- 未加引号的 UCS-2 编码号码（如 `02830203`）正确解码为可读号码
- 短信内容显示正常
